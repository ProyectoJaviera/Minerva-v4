app.explorer.service

Backtest exploratorio a pedido sobre el archivo de historial local (seccion «Indicadores»).

  • Fuente: un archivo SQLite aparte de la base del bot (EXPLORER_HISTORY_DB, por defecto ./history/history_v4.db), creado con scripts/update_history_file.py. Tiene las mismas tablas de mercado que usa el motor (velas LAST_PRICE y MARK_PRICE, funding y specs). Se abre en modo immutable de solo lectura: nada se escribe.
  • Estrategia: la confluencia de los indicadores que el dueno marca (app.explorer.confluence): todos votan alcista o bajista y se entra cuando todos coinciden, con una salida fija en ATR.
  • Motor: el mismo run_backtest de la Fase 2 (entrada en el open de la vela siguiente, comisiones, slippage, funding, liquidacion con MARK_PRICE).
  • Sin corte de datos: usa todo el historial del archivo. El corte del 2026-10-01 se quito el 2026-11-11 por pedido del dueno: esos datos ya se habian usado en el examen de la ronda 3.
  • Calentamiento previo: con una fecha de inicio, se cargan antes las velas de calentamiento de la estrategia y solo cuentan las operaciones que entran desde esa fecha (un rango corto ya no se queda sin senales).
  • Exploratorio: el resultado no se guarda en la base ni pasa por los criterios de la Fase 2. Con cada corrida va el control con direccion al azar (mismas velas de entrada y misma salida), la referencia «sin informacion de direccion».

El calculo corre en un hilo aparte con su propio bucle y su propia conexion, de a una corrida por vez, para no frenar el bucle del bot.

class ReadOnlyDatabase(app.persistence.database.Database):

Database abierta en modo immutable de solo lectura y sin tocar el esquema.

El archivo de historial es estatico mientras el dashboard lo lee; immutable=1 evita que SQLite intente crear el -wal o el -shm (funciona tambien con una carpeta montada de solo lectura en Docker).

class ExplorerRequest:

Una corrida exploratoria validada.

Attributes:
  • symbols: simbolos (1 a MAX_SYMBOLS).
  • timeframe: uno de TIMEFRAMES.
  • indicators: ids de INDICATORS (al menos uno), en su orden.
  • window: velas que dura el voto de un indicador de evento.
  • exit_name: clave de EXITS.
  • start_ms: inicio pedido (ms UTC) o None = desde el comienzo del historial.
  • end_ms: fin pedido (ms UTC) o None = hasta el final del historial.
  • min_agree: cuantos indicadores deben coincidir (None = todos).
  • pct_exit: (sl, tp, trailing) en % si exit_name es PCT_EXIT, si no None.

def validate_request( symbols: list[str], timeframe: str, indicators: list[str], window: int = 5, exit_name: str = 's2_tp2r', start: str | None = None, end: str | None = None, min_agree: int | None = None, sl_pct: float | None = None, tp_pct: float | None = None, trail_pct: float | None = None) -> ExplorerRequest:

Valida los parametros de una corrida y los normaliza.

Arguments:
  • symbols: simbolos (p. ej. ["BTCUSDT"]).
  • timeframe: 15m, 1h, 4h, 1d o 1w.
  • indicators: ids de los indicadores (uno o mas, sin limite).
  • window: velas que dura el voto de un indicador de evento (1 a MAX_WINDOW).
  • exit_name: salida (clave de EXITS).
  • start: fecha de inicio YYYY-MM-DD (UTC) o None.
  • end: fecha de fin YYYY-MM-DD (UTC, excluida) o None.
  • min_agree: cuantos indicadores deben coincidir (None, 0 o la cantidad elegida = todos).
  • sl_pct: SL en % del precio de entrada (obligatorio con la salida PCT_EXIT).
  • tp_pct: TP en % (opcional, solo con PCT_EXIT).
  • trail_pct: trailing en % (opcional, solo con PCT_EXIT).
Returns:

La corrida validada.

Raises:
  • ExplorerRequestError: si algun parametro no es valido.
